# TaskReady — AI Sana / Prompt Chiefs

MVP открытого каталога бизнес-задач: описание → уточнение → подтверждение карточки → рейтинг → отклик → ручной выбор → подтверждённый прогресс.

## Запуск

Node.js 22.16+ и npm. Из корня репозитория:

```sh
npm ci
npm run dev
```

Откройте адрес из терминала. `npm run build` проверяет TypeScript и собирает `dist`; `npm run preview` запускает собранную версию. `npm test` проверяет бизнес-логику и AI fallback.

Это интерактивный прототип без сервера и регистрации: роли переключаются действиями интерфейса, данные сохраняются в localStorage одного браузера. Для демонстрации бизнес и команды используют один браузер. Между устройствами данные не синхронизируются. Reset demo data заменяет задачи и отклики начальными примерами. Старые сохранённые данные автоматически не удаляются: после обновления нажмите Reset demo data, чтобы увидеть полный набор.

## Архитектура

React + TypeScript + Vite. `src/types/domain.ts` — модель, `src/data/seed.ts` — синтетические данные (5 черновиков, 5 карточек, 5 команд, 5 предложений). `src/lib/scoring.ts` — чистая формула рейтинга; `ai.ts` — адаптер вопросов; `storage.ts` — хранение и восстановление после повреждённого JSON. `App.tsx` связывает каталог, конструктор, отклики и подтверждение прогресса. Компоненты TaskEditor и ScorePanel показывают поля и расчёт.

## Рейтинг и правила каталога

| Показатель | Баллы | Минимум символов после trim |
|---|---:|---|
| Контекст и потребность | 20 | по 20 в каждом поле |
| Данные | 20 | 15 |
| Результат | 15 | 15 |
| Критерии успеха | 15 | 15 |
| Ограничения | 10 | 10 |
| Пользователи | 10 | 10 |
| Связь с бизнесом | 10 | контакт 5 и формат обратной связи 8 |

Это прозрачная эвристика полноты, а не автоматическая проверка истинности или содержательного качества. Бизнес проверяет факты и измеримость критериев перед публикацией. Каждая категория начисляется целиком или даёт 0; максимум 100. В редакторе показан предварительный расчёт. Только ручное Publish task сохраняет подтверждённую версию и меняет место в каталоге. Редактирование опубликованной задачи не меняет каталог до повторного подтверждения.

Уровни: 0–39 DRAFT, 40–69 WORKING, 70–89 READY, 90–100 PRIORITY. Каталог сортируется по убыванию рейтинга, есть фильтры по теме и уровню. Низкий рейтинг не запрещает публикацию и отклики. Минимум для публикации — название и исходное описание. Все поля карточки доступны студенту. Количество предложений не ограничено, несколько предложений могут быть приняты одновременно, можно отклонить все. Автоматического выбора нет.

После Accept бизнес вводит описание выполненного этапа и свидетельство результата, затем явно подтверждает его: команда получает 10 баллов один раз за предложение. Accept сам по себе баллов не даёт. Баллы сохраняются при перезагрузке, не дублируются повторным выбором команды. Это минимальная механика одного этапа, без полного трекера.

## AI: локальная заглушка и внешний адаптер

По умолчанию работает детерминированная локальная заглушка, разрешённая ТЗ; настоящая модель не вызывается. Она анализирует отсутствующие категории, задаёт минимум три вопроса, а ответы копирует в редактируемые поля без выдумывания фактов. Когда пробелов меньше трёх, задаёт дополнительные вопросы на конкретизацию.

Точный промпт доступен как `AI_PROMPT` в `src/lib/ai.ts`. Для внешнего сервиса задайте `VITE_TASK_DOCTOR_ENDPOINT` в `.env.local`. Адаптер отправляет POST `{ "prompt": "…", "task": { ...поля карточки } }`. Ответ:

```json
{"questions":[
  {"field":"need","question":"Что необходимо изменить?"},
  {"field":"data","question":"Какие данные доступны?"},
  {"field":"expectedResult","question":"Какой результат должна передать команда?"}
]}
```

При ошибке HTTP, неверном JSON, неизвестном поле, пустом вопросе, числе вопросов меньше трёх или таймауте 8 секунд используются локальные вопросы. Секретные API-ключи в клиент не помещаются; внешний endpoint должен сам обеспечивать вызов модели и CORS. Промпт запрещает выдумывание фактов и выбор исполнителей. AI не начисляет рейтинг и не получает профили участников.

## Демонстрация до 5 минут

1. 0:00–0:40: Reset demo data → Create task → Load feedback-analysis demo. Рейтинг 0: есть только контекст и название.
2. 0:40–1:40: AI Task Doctor. Ответы: потребность — «Выявлять повторяющиеся жалобы и передавать их ответственным сотрудникам»; данные — «Обезличенный CSV с 500 отзывами и категориями за последний месяц»; результат — «Веб-прототип группировки отзывов с фильтром по категории». Apply answers: предварительный рейтинг 55.
3. 1:40–2:40: заполнить Users «Руководитель клиентской поддержки»; Success criteria «Не менее 80% верных категорий на 100 контрольных отзывах»; Constraints «Локальный прототип за две недели без персональных данных»; Contact `owner@example.com`; Interaction format «Две консультации в неделю, письменная обратная связь в течение суток». Рейтинг 100. Confirm & publish → Publish task.
4. 2:40–3:30: в каталоге показать место, уровень и фильтры. Открыть карточку, выбрать команду и отправить идею «Классификатор отзывов», план «Разметка → базовая модель → интерфейс → оценка», срок «2 недели», ссылку `https://example.com/feedback-prototype` (демонстрационная ссылка).
5. 3:30–4:20: Proposals, выбрать задачу, сравнить предложения, вручную Accept или Reject. Показать, что каталог не назначает команды.
6. 4:20–5:00: для принятого предложения ввести «Показана первая версия интерфейса на 20 примерах, бизнес проверил результаты», подтвердить этап и показать +10. Перезагрузить страницу: задача, решение и баллы сохранены.

## Дополнительные ручные проверки

- Опубликовать название и короткий контекст с рейтингом 0, отправить отклик: ограничения по готовности нет.
- Edit as business: дополнить опубликованную задачу, подтвердить, проверить изменение позиции и сохранение откликов.
- Принять две команды на одну задачу; отклонить все; ни одно решение не меняет остальные автоматически.
- Пустые поля отклика и ссылки `javascript:`/`ftp:` отклоняются.
- Повредить `aisana.tasks.v1` в localStorage: приложение показывает предупреждение и демонстрационные карточки.
- Отправить внешний AI-ответ с неизвестным field: вместо падения доступны локальные вопросы.
