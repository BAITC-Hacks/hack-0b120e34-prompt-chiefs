# Проверка соответствия ТЗ AI Sana

Источник: «Новый документ (1).docx», предоставленный пользователем. Дата проверки: 23 сентября 2026. Документ использован как спецификация продукта. Число участников, фактические пять часов работы, ссылка сдачи и выступление команды не подтверждаются исходным кодом.

## Обязательные требования

| Требование | Результат и доказательство |
|---|---|
| Свободное описание | Конструктор принимает исходный текст без добавления фактов |
| Проверка полноты, ≥3 уместных вопроса | `ai.ts`: вопросы по отсутствующим полям, дополнительные вопросы на конкретизацию; проверено тестами и в Chrome |
| Редактируемая карточка, ручное подтверждение | 11 полей, отдельное подтверждение публикации; проверено в Chrome |
| Все поля карточки | Название, тема, контекст, потребность, пользователи, данные, ограничения, результат, критерии, контакт, взаимодействие; студент видит все 11 |
| Рейтинг 0–100 и расшифровка | Все семь весов из ТЗ; тесты удаления каждого поля и восьми граничных значений |
| Полный список недостающего | ScorePanel показывает все пропуски; подсказка привязана к своему критерию, а не к позиции в списке |
| Баллы только за содержательные сведения | Заполнитель из повторяющихся символов не засчитывается; критерии успеха требуют числа, процента или срока; контакт — email, телефон или @ник; покрыто тестами |
| Только подтверждённые сведения влияют на каталог | Редактор показывает предварительный рейтинг; опубликованный снимок меняется только после Publish task; проверено в Chrome |
| Дополнение и повторный расчёт | Edit as business сохраняет ID задачи и отклики; проверен рост 55 → 100 после подтверждения |
| Общий каталог, рейтинг и фильтры | Все опубликованные карточки доступны всем пяти демокомандам, сортируются по рейтингу; фильтры по теме и четырём уровням |
| Уровни видны в каталоге | Приоритетные карточки выделены рамкой и фоном; черновики — пунктиром и пометкой «Требует уточнения» |
| Рекомендации студентам (разрешено ТЗ) | `recommendations.ts`: задачи от 40 баллов по интересам команды; каталог не ограничивается, команда не назначается |
| Низкая готовность не закрывает доступ | Есть опубликованная карточка 0 баллов, форма отклика доступна; порога отправки в коде нет |
| Любая команда, неограниченные отклики | Выбор команды в форме; идея, план, срок и HTTP(S)-ссылка; лимитов нет |
| Сравнение и ручной выбор | Фильтр предложений по задаче, навыки и технологии команды, независимые «Принять»/«Отклонить»; можно выбрать несколько или отклонить все; после подтверждённого этапа решение окончательное, кнопки скрыты |
| Баллы только за фактический прогресс | Принятие не даёт баллов; бизнес описывает выполненный этап и подтверждает +10, повторное начисление запрещено; сохранение проверено |
| Содержательная AI-функция | Локальная заглушка: анализ пробелов и вопросы на языке интерфейса. Опционально — настоящая модель через `server/task-doctor.mjs` (Claude API, структурированный JSON) |
| Промпт, вход/выход, ошибочный ответ | Блок «Как работает AI-диагностика» в интерфейсе показывает режим, промпт, JSON-запрос и ответ; fallback при ошибках HTTP/JSON/сети/полей/числа вопросов, таймаут 20 секунд |
| Нет выдуманных AI-фактов | В карточку переносятся только ответы человека; тест неизменности остальных полей |
| Нет автоматического назначения и чувствительных признаков | AI получает задачу, не профили; выбор команды делает бизнес; профили содержат название, интересы, навыки, технологии |
| Минимальные наборы 5/5/5/5 | `seedDrafts` (доступны в конструкторе через «Пример черновика»), `seedTasks`, `seedTeams`, `seedProposals` на русском; проверены количества и связи. Текущий балл карточек вычисляется из полей, не хранится отдельным устаревающим числом |
| Запуск, валидация, структура | `npm ci`, сборка TypeScript/Vite; ошибки хранилища обрабатываются, пустая карточка и некорректная ссылка отклоняются |
| README и сценарий до пяти минут | Добавлены архитектура, формула, правила каталога, AI-контракт, ручные проверки, пример защиты с таймингом |

Это матрица покрытия, а не присвоение проекту 100 баллов: содержательное качество бизнес-описаний, полезность вопросов и оценку выступления определяет жюри.

## Выполненные проверки

- `npm run build`: успешно, TypeScript и производственная сборка Vite.
- `npm test`: 31/31 тестов прошли. Проверены веса, уровни, отсев заполнителей, измеримость критериев, формат контакта, наборы данных, язык вопросов AI, копирование только пользовательских ответов, некорректные AI-ответы, рекомендации, повреждение хранилища и окончательность прогресса.
- Headless Chrome через временный Playwright: 5 карточек → конструктор → 3 вопроса → ответы → 55 баллов → подтверждённая публикация → все поля карточки → отправка предложения → Accept → подтверждение этапа → 10 баллов → перезагрузка → баллы сохранены → редактирование до 100 → прежние 55 в каталоге до подтверждения → 100 после подтверждения. Ошибок JavaScript не обнаружено.

## Границы проверки

- Это локальный интерактивный прототип, допустимый ТЗ. Нет общего серверного хранилища между устройствами и проверки прав бизнеса; демонстрация проводится в одном браузере.
- Прокси к Claude проверен без ключа (400 на неверный запрос, 502 без ключа, CORS только для localhost); вызов реальной модели требует `ANTHROPIC_API_KEY` и в этой проверке не выполнялся. По умолчанию используется явно обозначенная локальная заглушка. Синтетические ссылки example.com иллюстрируют формат, а не реальные прототипы команд.
- Рейтинг проверяет наличие и минимальную длину сведений. Он не доказывает истинность данных или измеримость критериев: это ответственность подтверждающего представителя бизнеса.
- Реальный результат этапа подтверждает бизнес; приложение сохраняет описание свидетельства и подтверждение, но не проверяет результат самостоятельно.
- Перед сдачей команде нужно провести пятиминутную репетицию и передать ссылку на репозиторий либо архив. Публикация репозитория и реальное выступление не выполнялись в этой проверке.
